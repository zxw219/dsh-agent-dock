# DSH 其他小天才们

当前版本是开发原型：管理与演示流程已具备，Windows WorkBuddy 已接通真实侧栏标题读取和原生对话小窗打开。原生窗口跟随与切换隐藏已接线，并通过真实单窗口定位、隐藏、恢复测试；完整 DSH 点击流程及多屏缩放仍待验收，暂不作为稳定安装版本发布。

## 真实 WorkBuddy 列表

环境为 Windows 和 PowerShell 7（`pwsh.exe` 在 PATH 中，也可设置 `DSH_PWSH_PATH`）。先手动打开并还原 WorkBuddy 主窗口、展开需要的空间。插件管理卡片点击 **查看对话** 或 **刷新真实列表**，也可展开左侧 WorkBuddy 工作区，读取当前展开可见的分组和标题。成功后图标恢复彩色；读取失败时灰显并显示原因。图标只代表最近一次读取结果，不是持续的进程监控。

读取使用 Windows 标准 MSAA，不读取 WorkBuddy 文件。分组、标题及选择只存在页面内存中，刷新页面后需要重新读取。条目 key 是本次界面快照的定位标记，不是官方会话 ID；同名条目仍需在打开时重新验证。折叠、未加载、超出窗口的历史不保证包含。点击真实条目会重新读取界面并核对分组、标题和定位标记，再执行 WorkBuddy 原生的“在独立窗口中打开”菜单。小窗顶部标题核对成功后才报告打开成功；当前可见列表存在同名标题时拒绝自动打开。操作需要 WorkBuddy 主窗口可见且能取得前台焦点，会短暂移动鼠标并在未被用户移动时恢复。

真实读取已通过 Node → PowerShell 7 → MSAA 链路验证：当前展开侧栏 3 个分组、9 条标题。前端展示与异常处理通过模拟组件测试；不把这些测试当作真实 DSH 浏览器布局验收。

## 开发计划

当前通过标准辅助功能接口读取分组和标题，点击后执行原生独立窗口菜单。持久化 PowerShell 7 辅助进程使用公开 WinEventHook 和 SetWindowPos 跟随右侧预留区域；切离页面隐藏，返回页面恢复，旧请求通过临时 lease 隔离。打开下一条时上一小窗暂存隐藏；释放或插件卸载恢复受控窗口原来的位置与可见状态。小窗仍是独立 Windows 窗口，不是真正嵌入网页。

真实验证已确认单一小窗的位置后置检查、隐藏后置检查、重新挂接及释放恢复。另已实测 DSH 移动时无需新网页请求即可跟随；缩放后先隐藏旧区域，收到新区域后重新对齐；最小化隐藏，还原并重新核对渲染窗口后恢复。渲染窗口重建期间保留对话小窗身份，不使用失效坐标。41 项自动测试覆盖组件与本地路由/辅助进程协议，其中延迟打开后返回 DSH 和启动失败重试有回归测试。这些不等同于完整浏览器验收；多屏不同缩放、页面缩放、不同应用最小窗口尺寸、折叠/更多历史仍需实际验证。Android 控制保留为备用原型。

不读取第三方数据库、登录令牌或私有接口，不同步聊天，不修改第三方软件文件。参考项目列于 [THIRD_PARTY_NOTICES.md](./THIRD_PARTY_NOTICES.md)。

## 试用流程

1. 点击 DSH 左侧 **其他小天才们**，打开管理页。
2. 点击 **添加 WorkBuddy**（首次空列表）或 **添加智能体**。
3. 从列表选择智能体，图标自动匹配，不用自己填写。WorkBuddy 使用官方图标，其他内置名称暂用自动标识。可选的软件路径、将来打开对话的方式和切回 DSH 后的小窗行为收在 **高级设置** 中；这些连接选项目前只保存，不执行。
4. 点击 **填入三条示例**，也可以自己添加、修改、置顶或删除演示标题，然后保存。
5. 已打开的智能体工作区追加在左侧工作区的滚动列表内。点击 WorkBuddy 行可展开或收起演示对话；展开本身不切换右侧页面。管理卡片的 **查看对话** 则打开选择页面并展开列表。
6. 点击某条演示对话，右侧显示预留的小窗区域。点击 **返回 DSH** 恢复 DSH 对话；点击 **管理页** 返回设置。
7. 在管理卡片上点击 **关闭工作区**，左侧条目隐藏，设置和演示对话保留；点击 **打开工作区** 可重新显示。只有 **移除** 才删除本地入口及演示条目，且有确认步骤。

演示列表只有本地标题，没有真实聊天内容，也没有发送消息功能。智能体入口追加在左侧工作区列表下方，只显示名称，不添加连接状态后缀。WorkBuddy 使用官网下载的官方图标，当前未连接时灰显；只有真实连接验证成功后才能显示彩色。连接说明显示在设置页，不会根据演示数据声称软件正在运行。工作区位置通过 renderer 的 `data-slot="sidebar.workspaces"` 锚点查找其 `role="tree"` 滚动列表，追加插件自己的 Portal 节点，不替换原工作区；这是兼容适配，需要随 DSH 界面版本验证。软件路径不会被检查或执行；当前新增的侧栏读取不会打开、关闭或隐藏 WorkBuddy。真实条目已接原生小窗打开与跟随原型；高级设置的关闭/隐藏策略尚未启用，目前切换统一隐藏，不关闭原生小窗。

## 搜索本机智能体

管理页点击 **搜索本机智能体**，插件通过 DSH 公开的 `sessions.create` / `sessions.using` / `session.prompt` 和 `uiWorkspace.openSession` 新建并打开一个对话，自动提交内置检查提示词。重复点击在当前提交期间会被拦住，不会自动重复提交失败的请求。

检查由新会话中的 DSH 智能体执行：只读查看卸载注册表、开始菜单及常见安装位置，报告有证据的软件名称与程序路径；不打开软件、不读取账号、令牌或聊天内容。第一轮只报告结果；你选定添加哪些之后，再由该宿主会话执行配置操作。插件自身不做后台扫描，也不会把配置保存当作真实连接成功。新会话需要可用的模型与本机检查工具。

## 配置保存

`data/workbench.json` 保存智能体设置和演示标题。写入带版本检查，冲突时先重新读取设置再重试，避免覆盖其他页面的修改。首次使用为空列表。Android 配置单独保存在 `data/android.json`。

## Android 备用方案

管理页的 **Android 模拟器** 标签保留已有控制：启动、打开页面、隐藏、停止、刷新和设备设置。进入管理页或点击桌面智能体不会启动模拟器。Android 生命周期仍是此前原型，本次没有重新修复或承诺其窗口控制稳定性。

环境：Windows、Android SDK Platform-Tools、Android Emulator。默认 SDK 为 `%LOCALAPPDATA%\Android\Sdk`；可用 `ADB_PATH`、`EMULATOR_PATH` 覆盖。默认 AVD 为 `Pixel_Tablet`，serial 为 `emulator-5554`。

## 验证

运行 `node --test tests/*.test.mjs` 验证本地配置校验、持久化、并发冲突、磁盘失败、路由保护、设置表单和导航流程。这些是组件/控制逻辑测试，不等同于真实 DSH 浏览器验收。

不应把运行时 data、Android SDK、AVD、系统镜像、账号或聊天记录上传到代码仓库。打包文件列表不包含运行时 data。
